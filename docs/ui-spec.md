# UI spec

Four screens plus Unlock: Budget, Activity, and Categories & Rules in the nav, and Setup behind a cog button on the far right of the top bar. Categories & Rules and Setup have sub-sections; the top nav never grows.

## Top bar

Brand, then Budget | Activity | Categories & Rules. The ledger opens on the screen saved in Setup → Appearance (Budget by default). On the right: a quick sync dropdown (only when a connection exists; pick a connection to sync it now, disabled and showing "Syncing <name>…" while any sync runs, whether started here or in Setup), a pulsing "Categorizing with AI…" indicator whenever an AI run is in progress (from Setup, Activity, or after a sync), the Setup cog, and Lock.

## Keyboard (Activity)

The list wrapper is `tabindex=0` and takes focus on open. Letters always go to the category typeahead, so no category name is unreachable. Commands use arrows, Space, Enter, Esc, and the ⌘/Ctrl chords.

| Key | Action |
| --- | --- |
| `↑` / `↓` | Move cursor (the row scrolls into view) |
| type letters | Category typeahead (exact name, else unique prefix) |
| `Enter` | Apply the matched category to the selection, or the cursor row. With nothing typed: open or close the row editor |
| `Space` | Toggle select (only when nothing is typed) |
| `⌘E` / `Ctrl+E` | Exclude the selection or cursor row (includes again if all targets are already excluded) |
| `⌘⌫` / `Ctrl+⌫` | Delete. First press arms, second press deletes; anything else disarms |
| `/` | Focus search. `Esc` in search clears it and returns to the list |
| `Esc` | Clear typed text, then close the editor, then clear the selection |
| click category | Set category from the row dropdown |
| click row or checkbox | Expand the editor, or toggle select |

## Screens

### Unlock
Folder path + Browse + passphrase. Enter submits. Empty folder creates a ledger.

### Budget
`‹ ›` and `←`/`→` change month; "This month" appears when away from it. Summary tiles: spent, income (only when something is marked income this month), capped total, left or over count, and "N to review" (opens Activity filtered to this month's uncategorized rows). Each category row: spent / cap, left or over, bar. The bar and the amount left use four colors from the current theme: well under, mid (half up to 80%), near (80% through the cap), and over. Ledger is sage, gold, burnt orange, terracotta. Ink is teal, slate, copper, rose. Paper is forest, dark gold, sienna, brick. Newsprint is pine, indigo, sepia, brick. Uncapped rows say "no cap" and are muted. Sub-categories sit indented under their parent; a parent's spent is its own plus its sub-categories', and the Spent tile sums top-level rows only. Categories with In budget off (and everything under one) are not on this screen and not in the tiles. Click a row → Activity filtered to that category and month (a parent's filter covers its sub-categories).

Empty: no categories → "Add categories" button (opens Categories & Rules). Categories but no caps → hint pointing at Categories & Rules.

### Activity
Filter bar: Uncategorized | All | AI | Excluded chips (AI lists rows the AI categorized, for review; Excluded lists rows marked excluded so they can be found and included again), search (payee, notes, or amount), account, category, month. The Activity tab opens on the chip saved in Setup → Appearance (All by default). "Reset" appears when the list is off that chip or any other filter is set, and returns to that chip. The meta line leads with a select-all checkbox (same size and left edge as the row checkboxes; checked only when every row on screen is selected, and clicking it selects all rows shown or clears the selection), then count, outflow and inflow totals, a "Categorize N with AI" button on the Uncategorized chip when a provider is configured (N counts the rows on screen the AI can take: uncategorized, not excluded, transfer, income, or split; only those rows are sent, and answers apply to them alone), and the typeahead state (typed text → guessed category) or the key legend.

Rows group by month with a sticky header. Each row: checkbox (1.25rem, easy to hit), day, payee with tags (pending, transfer, card payment, loan payment, income, split, excluded, ai) and a note preview, account, category dropdown, signed amount. Hidden accounts' rows only appear when that account is picked in the account filter (listed as "Name (hidden)"). Categorizing a payee also fills other uncategorized matches; toast says how many.

Bulk bar (when anything is selected): set category, "Mark as…" (transfer, credit card payment, loan payment, income, not a transfer, not income), exclude, delete (two-step), clear.

Editor (expanded row): category (with Ask AI beside it, only on rows the AI can take, when a provider is configured; sends just that row and applies the answer to it alone), payee, notes, date, amount. There is no Save button: each field saves when it loses focus or takes Enter, as its own undoable change ("Renamed A to B.", "Changed notes on X." / "Cleared notes on X.", "Moved X to 2026-09-05.", "Changed amount of X to -$42.00."); a blank payee, bad date, or bad amount toasts the problem and puts the field back. Action row: a "Mark as…" select inline with the buttons (transfer, credit card payment, loan payment, income, excluded; shows the row's current flag and applies as soon as it changes, resetting the other flags so the row ends up with exactly the chosen one; toasts "Marked <payee> as …" or "Unmarked <payee>."), Split… (collapsed by default; amounts must sum to the total), Raw data and AI trace (only when Setup → Debug is on; see Setup), Create rule… (collapsed by default; the same pattern list and action as Categories & Rules → Rules, prefilled with one row holding the row's exact payee and its current category or flag, with the live preview; Add rule creates the rule, applies it to every matching row, toasts the count, and closes the panel. When rules exist, an "Add to" picker above the form lists them as `Outcome: pattern…` (same format as the Rules list); picking one hides the action select, keeps the pattern list editable so wildcards or more rows can be added, and the button becomes Add to rule, which appends each row as a new `|` alternative on that rule (duplicates skipped), keeps its action and position, applies it, and toasts the count), Delete (two-step). Esc closes. Transfer, card payment, loan payment, income, and excluded rows leave the Uncategorized list and never count toward caps or the month's spent total. Card and loan payments are transfers with a label, so the money you already spent on the card is not counted twice.

Empty: Uncategorized chip with nothing else filtered → "Everything is categorized." AI chip with nothing else → "Nothing categorized by AI yet." Excluded chip with nothing else → "Nothing is excluded." Any other filter with nothing → "Nothing matches these filters" with a reset button (back to the saved chip). No rows on that chip → "No transactions yet."

### Categories & Rules
Sub-sections: Categories & caps, Rules.

- Categories & caps: a "+ Add" row sits below the last category; clicking it turns the row into a name input (autofocused; Enter or Save adds a top-level category, Esc or Cancel closes, toasts "Added <name>."). Each top-level row has a "+" button beside the category name (labelled "Add a sub-category under <name>"); clicking it opens the same name input as an indented row right after that category's last sub-category (or after the category itself when it has none), and saving adds the sub-category under it. Only one add row is open at a time. Nesting is one level: a sub-category cannot have its own, so sub-category rows have no "+". Each row leads with ▲/▼ arrows that move the category one step among its siblings (top-level rows, or one parent's sub-categories; disabled at the ends); the order is stored as `sort_order`, a parent is always directly followed by its sub-categories, and Month, Activity dropdowns, and the AI list all follow it. Sub-category rows are indented and show their own name; everywhere else (Activity rows and pickers, rule outcomes, the AI list) a sub-category is labelled `Parent › Child`. Month stepper for caps with "This month". A cap set in a month stays in force for every later month until it is changed there, so there is nothing to copy forward; earlier months keep whatever was in force then. Table: name (Rename inline, Enter/Esc; while renaming, a "Top level / Under <parent>" select re-parents on change, hidden for a row that has sub-categories), description (free text, saves on change; the context the AI categorizer sees for that category), In budget checkbox (on by default; off means no cap, not on Month, not in the month's spent, while the category still takes transactions; unticking a parent also unticks its sub-categories, and a sub-category's box is disabled while its parent is off; an off-budget row keeps normal ink for its name, only its spent figure is muted, so it does not read as disabled), Send to AI checkbox (on by default; off keeps the category out of the option list the AI categorizer sees, while rules, memory, and hand edits can still assign it; unticking a parent also unticks its sub-categories, and a sub-category's box is disabled while its parent is off), cap input (blank = no cap, saves on change; replaced by "off budget" when the row is out), spent (a parent's includes its in-budget sub-categories'), Delete (two-step, explains consequences; deleting a parent deletes its sub-categories too).
- Rules: "If description matches <patterns> then <action>". The patterns are a list, one input per alternative, each with a Remove button, "or" in front of every row after the first, and an "+ Add another pattern" button that appends a blank row and focuses it (the list never goes empty; removing the last row leaves one blank). Each alternative is a case-insensitive wildcard over the whole description (`*` any run, `?` one character; `*costco*` is the old "contains costco"); a `|` typed inside a row still splits into alternatives. Inputs turn off spellcheck, autocorrect, and autocapitalize so the webview does not swap `'` for `’`; curly quotes that get through are stored straight and match either spelling. Patterns are stored in canonical `a | b` form and the action is a category or one of mark transfer / mark card payment / mark loan payment / mark income / exclude. A matches column sits to the right of the pattern list and action (below them in narrow windows). While a pattern is typed, it lists every transaction the whole rule matches (newest first, with a count), headed "This pattern matches", or "This rule matches" while editing. While one pattern input has focus, the column narrows to that alternative alone, headed like `*ARCO* matches`; a blank input falls back to the whole rule. With nothing typed and nothing being edited it says to pick Edit on a rule or type a pattern. When nothing matches, the empty state says patterns cover the whole description and, if wrapping each alternative in `*` would match rows, names that form with its count. Add rule (Enter works) applies the new rule to every existing transaction it matches, including rows categorized by hand, and reports how many rows changed; a row an earlier rule already claims is left alone. Flag rules only set the flag and never touch the category; deleting a rule leaves rows as they are. List shows the outcome first, then the canonical pattern cut to 40 characters with an ellipsis, like `Gas: *ARCO* | *COSTCO GA…` (the full pattern is in the row's tooltip), with Edit and Delete. Edit loads the rule into the form (one row per alternative, and the action) and the matches column shows every transaction the rule matches, updating as the pattern is edited and narrowing to whichever pattern input has focus; the button becomes Save rule with a Cancel beside it (Esc also cancels). Save updates the pattern and action, keeps the rule's position, applies it to every row it now matches (same winner logic as Add), and reports the count. Rows the old pattern matched are left as they are. Deleting the rule being edited clears the form.

### Setup
Sub-sections: Connections, AI, Debug, Log, Appearance, Passphrase.

- Connections: cards with name, "Synced 5 min ago" / "Never synced", last error, the connection's accounts each with Hide/Show (hidden accounts drop out of Activity, the uncategorized count, caps, and the month list; rows stay in the ledger), Sync now (disabled while any sync runs), Remove (two-step; removes its accounts and transactions). The token form shows on its own when there are no connections, otherwise behind "Add another connection".
- AI: provider dropdown (every `ai::PROVIDERS` entry), then a hint with the selected provider's `description()` and, when it has one, its `link()` as an anchor (LMR links to github.com/faulker/lmr-rs). A provider with a `warning()` (LMR) shows that next as a gold hint: a model you host will not match typesafe.ai, and openbmb/MiniCPM5-2B-GGUF is the model to serve for the best local results. For a provider with a `default_endpoint()` (LMR): a Server URL field (placeholder is the default, blank keeps it; on Save a non-blank value must pass `url_allowed`, else "Server URL must be https, or http on a local network address.") and a "Server certificate (PEM, optional)" textarea (on Save a non-blank value must parse as PEM, else "Server certificate is not valid PEM."); both hidden and not saved for other providers. API key (password field; labeled "API key (optional)" for a provider whose `needs_key()` is false; never echoed back, placeholder shows `****` and a hint says a key is saved once one exists), threshold as a whole percent (default 70), "Run after every sync" checkbox, Save. Below, a "Categorize with AI" card showing the uncategorized count; the button is disabled while a sync or AI run is in progress, when the provider is not configured (no provider chosen, or a key it needs is missing), or with nothing to do. The run toasts "AI categorized N rows across M payees, K below threshold." plus any provider error. When the after-sync toggle is on, sync toasts end with the same sentence. Below that, a "Debug a transaction" card: a search box (payee, notes, or amount) narrows a dropdown of up to 50 rows (`date · payee · amount · category`, any row, categorized or not); "Send to AI" (disabled when the provider is not configured, without a pick, or while any sync or AI run is in progress) sends that one row and shows what was sent (payee and money in/out), then each HTTP exchange as a Request block (method, URL, pretty-printed JSON body) and a Response block (HTTP status, pretty-printed body; "no response (network error)" when the transport failed), each body field with a Copy button in its top-right corner (copies the payload; the button reads Copied after a click), and a one-line outcome. When the response includes per-category probabilities, that line names the highest-rated category and its rating, then the pick's confidence, then how long the call took, retries included ("Highest: Dining at 71%. Confidence 91%. Took 1.2 s."). If the highest rating is a different category than the pick, both are named ("Highest: Gas at 55%. Picked Dining at 91% confidence. Took 12 s."). With no distribution it keeps the pick line and still reports the time ("Picked Dining at 91% confidence. Took 340 ms.", "Picked other (nothing fits) at 40% confidence. Took 340 ms.", or "Failed: <error>. Took 80 ms."). Retries show as numbered attempts. Nothing is cached or applied, and headers (the key) are never shown.
- Debug: one checkbox, "Show debug views on transactions" (stored in the ledger's `meta`, off by default; toasts "Debug views on." / "Debug views off."). When on, every Activity editor's action row gains Raw data and AI trace. Raw data shows the bank's JSON for the transaction and for its account, pretty-printed (a split line shows its parent's; a row imported before raw data was kept says so and fills in on the next sync). AI trace shows the recorded answer for the row's payee, if the AI was ever asked: provider and when, then the same Request and Response blocks as the Setup debug card and the stored pick line ("Picked Dining at 91% confidence.", or the failure), read from the ledger without sending anything ("The AI has not been asked about this payee." otherwise). That recorded line has no rating or duration, because the pass does not keep them.
- Log: a card at the top sets how long status messages stay up (whole seconds, 1 to 120, default 5, saved on change in the ledger's `meta` as `status_timeout_secs`). Below it, every status this session, newest first. Entries for transaction changes (field edits and Mark as in the editor) carry an Undo button until used; an undone entry is struck through with an "undone" tag.
- Appearance: a Theme select (Ledger, Ink, Paper, Newsprint). Ledger is the default: warm near-black, cream ink, gold. Ink is a cooler dark (blue-black, pale ink, copper). Paper is warm ivory with dark ink and gold. Newsprint is cool gray paper with near-black ink and indigo. The choice saves on change in the ledger's `meta` as `theme` and applies at once ("Theme set to Ink."). An unknown or blank saved value falls back to Ledger. Unlock stays on Ledger until a ledger opens; after a theme is chosen, locking keeps it until the app closes. Below that, "Open on" (Budget, Activity, or Categories & Rules; stored as `open_screen`, Budget by default; applied the next time the ledger unlocks; "This ledger will open on Budget.") and "Activity opens on" (Uncategorized, All, AI, or Excluded; stored as `activity_scope`, All by default; the chip the Activity tab and Reset use, from the next click; "Activity will open on All."). An unknown or blank value for either falls back to the default.
- Passphrase: current, new, and confirm (password fields; Enter submits). Change passphrase re-encrypts the ledger under a new salt. Before that rewrite, the current `ledger.enc` is copied to `ledger.enc.backup` (still encrypted with the current passphrase). That backup is removed only after a later unlock succeeds with the new passphrase. A failed unlock leaves it. A wrong current passphrase toasts "Current passphrase is wrong." and leaves the file alone. A blank new passphrase toasts "Enter a new passphrase." The same passphrase toasts "New passphrase is the same as the current one." A mismatch toasts "Those passphrases do not match." Success toasts "Passphrase changed. ledger.enc.backup will be removed the next time you unlock with the new passphrase." and clears the fields. The hint says that if the new passphrase will not unlock, quit, replace `ledger.enc` with `ledger.enc.backup`, and use the previous passphrase. The passphrase is still never stored.

## States
- Status: floating toast bottom-right, can be closed. Does not change layout. A gold bar along its bottom edge shrinks from full to empty over the timeout set in Setup → Log (5s by default) and the toast hides when it runs out; hovering the toast pauses the bar. The timer is a CSS animation in the webview (`onanimationend` expires the toast), not a Rust sleep, and a newer message replaces the toast with a fresh bar. Toasts for transaction changes carry an Undo button and stay 3s longer; Undo puts the row back and toasts "Undone."
- Provider errors: sanitized `errlist` on the connection card, in the toast, and in the Log.
- Wrong passphrase: error on Unlock, do not create a second ledger.
- Never show bank credentials, Access URLs, setup tokens, or AI keys in logs or flash copy.
